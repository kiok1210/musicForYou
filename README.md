# VinylBox

YouTube 音乐下载缓存 + 黑胶唱片质感的本地播放器（Windows 桌面端）。

搜索或粘贴 YouTube 链接，把音频缓存到本地，然后用一台虚拟唱机播放它——唱片会随音乐旋转，唱臂在播放时落下、暂停时抬起。

## 功能

- **搜索 / 链接解析**：支持关键词搜索，也支持直接粘贴 YouTube 视频或分享链接
- **本地缓存**：下载原始音频轨（M4A）并保存封面，缓存后的曲目离线可播
- **黑胶播放器**：沟槽旋转 + 固定反光的唱片、可落臂的唱臂、走带进度与音量控制
- **自动歌词**：自动匹配歌词，支持各种语言，非中文默认附中文翻译，逐行高亮跟随
- **播放列表**：单曲 / 列表循环、上一首 / 下一首
- **标签分类**：自动落标签（语言 / 版本 / 乐器 / 风格 / 场景 / 时长），支持手动增删与多选筛选
- **分类发现**：音乐 16 个 + 有声书 11 个分类一键搜一批，下载后自动归类，分类看板显示各分类的缓存数与总时长
- **播放记忆**：随时关闭，重开回到上次的曲目与进度，点播放即续唱
- **听书增强**：七档倍速、睡眠定时、按倍速折算的剩余时间、长内容断点续听
- **音乐库**：收藏、筛选、在文件夹中显示、单曲删除、清空缓存
- **下载队列**：并发下载、实时进度 / 速度 / 剩余时间、任务取消
- **代理兼容**：跟随系统（含 PAC 脚本）/ 手动指定（HTTP、SOCKS5）/ 强制直连

## 环境要求

- Windows 10 / 11 x64
- Node.js 18+
- Python 3.9+（用于首次自动装配下载核心）

`yt-dlp` 与 `ffmpeg` 无需手动安装：首次点「初始化组件」时会通过 PyPI 装进应用自己的目录
（`%APPDATA%\VinylBox\pylibs`），不污染系统 Python 环境。若本机已有 `yt-dlp`，
设置环境变量 `YTDLP_PATH` / `FFMPEG_PATH` 即可直接复用。

## 开发与打包

```bash
npm install
npm run dev          # 启动开发模式
npm run typecheck    # 类型检查
npm run build        # 构建产物到 out/
npm run dist         # 打包到 release/，一次产出三种形态
```

`npm run dist` 同时产出三种形态，按场景取用：

| 产物 | 大小 | 启动 | 用途 |
| --- | --- | --- | --- |
| `VinylBox-<版本>-win-x64-setup.exe` | 78 MB | < 1s | **安装版**：可选安装目录，建桌面与开始菜单快捷方式 |
| `VinylBox-<版本>-win-x64.zip` | 106 MB | < 1s | **绿色版（推荐）**：解压即用，适合放 U 盘或拷贝分发 |
| `VinylBox-<版本>-win-x64-portable.exe` | 78 MB | 10s+ | 单文件便携版：**每次启动都要自解压**，日常不推荐 |
| `release/win-unpacked/` | — | < 1s | 未压缩的绿色目录，等价于 zip 解压后的内容 |

三种形态共用同一份数据目录 `%APPDATA%\VinylBox`，可以混着用、互相接续。

**关于便携版的启动速度**：`portable.exe` 是 NSIS 自解压包，每次运行都要把整个应用
（解压后约 200 MB）释放到 `%TEMP%` 再启动，还要加上杀毒软件对新生可执行文件的实时扫描，
实测冷启动 13 秒以上。`unpackDirName` 也**无法**跳过重复解压（实测第二次仍是 13.8s）。
需要「免安装」时请直接用 **zip 绿色版**：解压一次，之后启动与应用本体一致（< 1 秒）。

应用自身的启动耗时分布（`npm start` 时输出 `[boot]` 打点）：

```
[boot] app ready       +64ms
[boot] store ready     +100ms
[boot] window created  +183ms
[boot] renderer loaded +862ms   ← 加载执行前端包，属正常水平
[boot] window shown    +946ms
```

## 代理配置

程序按当前网络环境自动选择策略，在「设置 → 网络代理」中切换：

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| 跟随系统（默认） | 开了 Clash / v2ray 等系统代理，或使用 PAC | 读取 Windows 的 PAC 脚本与系统代理设置并自动解析 |
| 手动指定 | 代理未走系统设置，或需要单独指定 | 使用填写的地址，`http://` 与 `socks5://` 均支持 |
| 不使用 | 本机可直连 YouTube | 强制直连，忽略所有代理 |

几点说明：

- PAC 返回的候选里**优先采用 HTTP 代理**，因为 yt-dlp 使用 SOCKS 需要额外依赖（安装组件时已一并装好 PySocks，SOCKS 也可用）
- 手动代理会同时作用于应用自身与 yt-dlp，保证连通性检测结果与实际下载行为一致
- 界面顶部的「YouTube 不可达」提示可直接点「重新检测」或「去设置」

## 歌词与翻译

播放任意缓存曲目会自动匹配歌词，不需要手动搜索。

**歌词来源**（按优先级）

1. **LRCLIB** — 开放歌词库，带 LRC 时间轴，文本最准确
2. **YouTube 字幕** — 视频自带字幕（含自动生成的 ASR），在线兜底
3. **本地语音识别** — 完全离线，前两条都拿不到时手动触发

匹配时会把 YouTube 标题里的 emoji、`Official Video`、`｜` 分段等噪声剥掉，并按时长就近选取最吻合的版本。
字幕与歌词库的限流、超时会被识别为**临时状态**——不写缓存，下次播放自动重试。

**中文翻译**

- 检测到歌词不是中文时自动翻译，与原文逐行对照显示
- 如果 YouTube 正好提供 `zh-Hans` 自动翻译字幕，直接采用——时间轴天然对齐，质量通常更好
- 否则调用翻译接口：Google 翻译（经代理）→ MyMemory（直连），多行批量失败时自动退化为逐行
- 翻译服务全部不可用时保留原文，并在面板底部说明原因

**界面操作**

- 唱片视图下方显示当前歌词行，点击即可展开完整歌词面板
- 面板内当前行高亮、自动滚动居中，已唱过的行渐暗
- 底部显示来源、是否已翻译、命中的曲名，并提供「重新匹配」
- 可在「设置 → 歌词」关闭自动翻译

歌词结果会缓存在 `lyrics/<视频ID>.json`，同一首歌不会重复请求。

### 本地语音识别

在线歌词全部拿不到时，在歌词面板点「本地识别」：用 ffmpeg 把音频转成 16kHz 单声道，再用
faster-whisper（CPU / int8）识别出带时间轴的歌词，非中文结果同样自动补中文翻译。
首次使用会自动安装组件并下载模型（`tiny` 约 75MB），之后完全离线。

也需要了解它的现实限制：

- 语音模型以「说话」为主训练，对**唱歌**的准确度明显低于说话，中文歌尤其明显
- 因此程序会从标题推断语言并作为提示传入——不加提示时 Whisper 会把中文歌声**意译成英文**
- CPU 上 `tiny` 约 7x 实时，`base` 约 0.4x 实时（1 小时音频用 base 需要数小时）
- 所以默认 `tiny`；长音频与对准确度有要求的场景，建议优先等在线匹配

模型缓存在 `models/`，可重复使用；识别中间产物在 `work/`，识别结束即清理。

## 标签与分类

每首缓存曲目会自动打上多个标签，不需要手动维护。全部依据本地已有信息推断，不额外发起网络请求：

| 维度 | 举例 | 依据 |
| --- | --- | --- |
| 语言 | 中文 / 英文 / 日文 / 韩文 | 歌词语言检测 |
| 版本 | 现场版 / 翻唱 / 混音 / 伴奏 / 不插电 / 串烧 | 标题关键词 |
| 乐器 | 钢琴 / 吉他 / 小提琴 / 萨克斯 / 管弦乐 / 古筝 | 标题关键词 |
| 风格 | 爵士 / Lo-Fi / 电子 / 摇滚 / 古典 / 民谣 / R&B / 说唱 / 氛围 | 标题 + YouTube 分类 |
| 场景 | 助眠 / 放松 / 学习 / 咖啡厅 / 开车 / 深夜 / 怀旧 | 标题关键词 |
| 时长 | 短曲 / 长曲 / 合辑 | 音频时长 |

用法：

- 下载完成即落标签；歌词匹配出来后自动补上「语言」与「纯音乐」
- 库顶部的标签栏点击可**多选**，多个标签取交集，方便逐步收窄
- 直接点标签上的 `×` 可移除；用标签图标按钮添加自己的标签
- 手动标签带一个小圆点，重算自动标签时不会被覆盖
- 标签栏右侧的刷新按钮可重算全部自动标签

## 分类发现

内置 27 个分类，分属两个平级的大类：

**音乐**（16 个）：爵士、Lo-Fi 学习、古典、中国风、民谣、电子、摇滚、R&B / Soul、说唱、
助眠放松、咖啡厅、深夜氛围、运动跑步、日漫金曲、影视配乐、怀旧金曲。

**有声书**（11 个）：网络小说、有声小说、评书相声、历史人文、商业财经、儿童故事、
外语学习、哲学心理、传记纪实、文学经典、知识杂谈。

其中「网络小说」与「有声小说」刻意分开：前者是起点 / 番茄 / 晋江的网文朗读，
后者偏出版与经典小说。两者的特征词按品类词（玄幻、修仙、重生）和获奖 / 出版词
（茅盾文学奖、当代文学）区分，且网络小说排在前面——网文标题常只写品类词。

有声书是与音乐**平级**的一大类，不是音乐底下的一个分类——它有自己的一整套子分类，
发现页也单独占一个区。它的关键词刻意全用中文：YouTube 上这类内容的标题与上传者
几乎都是中文站，用英文词搜出来的多半是英文有声书，不是国内听众要的那批。

每个分类同时承担两件事（定义见 `src/main/catalog.ts`）：

| 用途 | 说明 |
| --- | --- |
| **发现入口** | 每个分类内置多条中英混排的查询词，**每点一次轮换一个**，避免同一分类永远只看到同一批结果 |
| **自动归类** | 下载后按「标题 + 频道名」匹配分类特征词，命中即打上**分类名标签** |

关键设计：**分类名本身就是标签**。所以分类看板、筛选栏、标签云全部复用现有的标签体系，
没有第二套数据要维护，改一处两边同步。

另一个隐性规则：**分类在 `MUSIC_CATEGORIES` / `AUDIOBOOK_CATEGORIES` 里的顺序就是优先级**。
`inferCategory` 遍历时取得分更高者、同分取先出现者，所以特征词会互相命中的分类必须按
紧密度排序。例如「日漫金曲」必须排在「影视配乐」之前——动漫标题里的 `theme song`
两边都会命中；「网络小说」必须排在「有声小说」之前同理。

### 二级子分类

每个一级分类都能再往下切一层，一共 118 个小类。分类卡片右下角悬停会浮出
`› 5` 这样的小按钮，点进去是该分类的小类列表，再点小类直接按它的关键词搜索：

```
爵士                          ← 一级，点它搜 smooth jazz music
  ├ Smooth Jazz               ← 二级，点它搜 smooth jazz music
  ├ Bossa Nova
  ├ 爵士钢琴
  ├ 人声爵士
  └ 酷派爵士
```

- 小类的搜索词独立于一级分类，不再共用一级那几个关键词
- 一级分类照旧可点，搜的是它自己的一组词
- 数据集中在 `catalog.ts` 的 `SUBCATEGORIES` 里，按一级分类 id 挂载，
  不必去改 27 个分类块
- 自建分类暂无小类，需要时按同样的结构补即可

### 内容源

搜索框左侧的下拉就是源切换，内置 9 个站点：

| 源 | 站内搜索 | 说明 |
| --- | --- | --- |
| YouTube | `ytsearch` | 默认源，曲库最大，字幕最全 |
| 哔哩哔哩 | `bilisearch` | 国内直连最快；境外代理出口可能被区域限制 |
| SoundCloud | `scsearch` | 独立音乐人与 DJ 混音，国内需代理 |
| NicoNico | `nicosearch` | 日系同人，需代理 |
| Bandcamp / Vimeo / Dailymotion / 抖音 / 西瓜视频 | 无 | 只能粘贴链接 |

**yt-dlp 支持上千个站点，但提供站内搜索的只有少数几个**（判据是 extractor 里的
`_SEARCH_KEY`，实测可用的就上面四个）。所以源分两种能力：有搜索键的能进搜索框与
发现页，没有的只能粘贴链接——但下载、缓存、自动归类对两者一视同仁。

设置面板「内容源」里可以自己加源，填三项：

| 字段 | 说明 |
| --- | --- |
| 名称 | 显示用的名字 |
| 域名 | 逗号分隔，用于粘贴链接时认出内容来自哪里 |
| 搜索键 | yt-dlp 的站内搜索前缀，留空表示这个源只支持粘贴链接 |

- 存放在 `sources.json`，重启后自动载入
- 内置源只读，自建源可删；删掉的正好是当前源时自动退回 YouTube

换源之后有三处必须跟着走，否则会静默失效：取直链要用曲目的原始页面地址（不能拼
YouTube 链接）、CDN 的 Referer 要按站点给（拿 YouTube 的 Referer 请求 B 站 CDN 会被拒）、
`looksLikeUrl` 得认得非 YouTube 域名（否则粘贴的链接会被当成关键词去搜索）。

### 自建分类

发现页末尾的「自定义分类」卡片就是入口，填三项即可：

| 字段 | 说明 |
| --- | --- |
| 名称 | 分类名，同时会成为自动标签 |
| 搜索关键词 | 逗号分隔；填多个则每点一次轮换一个 |
| 描述 | 一句话说明，可留空 |
| 类型 | 建到「音乐」还是「有声书」大区下 |

归类用的特征词由「名称 + 关键词」自动派生（中文整串、英文按空格与标点切开），
配色从预设色板按顺序分配，这两项都不用填。

- 存放在 `categories.json`，重启后自动载入并注入分类目录
- 自建分类参与搜索、归类、标签体系，与内置分类完全同等
- 悬停卡片右上角出现删除按钮；删除分类**不会**删歌，只会清掉对应的自动标签
- 内置分类只读，自建上限 20 个

界面：「发现」页就是分类墙，每张卡片显示该分类已缓存多少首、总时长多少；点卡片直接搜一批，
结果列表可一键缓存。顶部搜索框照常可用，两者互不冲突。

归类的阈值按中文特性设定：`scoreByMarkers` 对英文「整词」给 3 分、对「包含」给 1 分，
而中文没有空格分隔，绝大多数命中都走包含分支，所以阈值取 1。低于阈值宁可留在「未归类」，也不乱贴标签。

## 播放记忆

播放现场会持续落盘到 `playback.json`：当前曲目、播放位置、音量、静音、循环模式与整个队列。

- 播放中每 3 秒保存一次，关闭窗口前再刷写一次，最多丢几秒
- 重新打开自动还原到上次位置，但**保持暂停**，不会一启动就出声——点播放即从中断处续唱
- 上次的曲目若已被删除，则安静跳过
- 只预加载元数据时浏览器会限制跳转范围，因此还原阶段会临时放开预加载并校验结果，确保长音频也能精确落到断点

## 听书

有声书、朗读与长音频走同一套播放器，但额外补了几件音乐用不上的能力：

| 能力 | 说明 |
| --- | --- |
| **倍速** | 0.75 / 1 / 1.25 / 1.5 / 1.75 / 2 / 2.5 七档，点播放器右侧的倍速按钮循环切换，正在播的歌立刻变速 |
| **睡眠定时** | 15 / 30 / 45 / 60 / 90 分钟任选，到点先把音量淡出到 0 再停，不会戛然而止 |
| **剩余时间** | 按当前倍速折算——1.5× 时显示的才是「实际还要听多久」 |
| **断点续听** | 每 3 秒记录一次播放位置，超过 10 分钟的长内容点开自动续听 |

- 进度太靠前（< 15 秒）或已接近结尾（< 30 秒）都视为「已听完」，不会反复重听同一段
- 倍速、定时、进度全部本地持久化，换歌、关窗、重启都不丢
- 发现页的「有声书」分类可以直接搜一批，缓存的曲目按标题 / 频道自动归类
- 曲库列表里，长内容下方会画一条细进度线，鼠标悬停能看到具体位置

倍速档位、断点续听的边界、睡眠定时的换算都在 `src/shared/portable/playback.ts`
——这是与 EchoPod 共用的纯函数模块，没有任何 DOM 依赖。

## 缓存位置

全部数据位于 `%APPDATA%\VinylBox`：

```
VinylBox/
├── media/       音频文件（<视频ID>.m4a）
├── covers/      封面图（<视频ID>.webp）
├── lyrics/      歌词缓存（<视频ID>.json）
├── subs/        下载字幕的临时目录
├── categories.json   用户自建分类
├── library.json      曲库索引
├── pylibs/      私有 Python 依赖（yt-dlp / imageio-ffmpeg / PySocks）
├── library.json  曲目索引（含标签）
├── playback.json 播放现场（断点续唱）
├── settings.json 设置
└── bin/          可选的 yt-dlp / ffmpeg 二进制
```

启动时会自动归集 `media/` 中尚未入索引的音频文件，并异步补齐曲目信息。

## 与 EchoPod 的复用关系

[EchoPod](../bokeForYou) 是同一套技术底座下的姊妹项目（英语播客缓存播放器）。
两者的通用逻辑集中在 `src/shared/portable/`：**纯逻辑，不 import electron、不 import react、
不读写文件、不发请求**，整目录复制到另一侧即可使用，不需要改构建配置。

| 模块 | 内容 | 来源 |
| --- | --- | --- |
| `subtitles.ts` | LRC / WebVTT / 纯文本解析、语言检测、双语时间轴对齐 | VinylBox |
| `ytdlp-output.ts` | 下载进度行解析、阶段标记、报错中文化、链接判别 | VinylBox |
| `format.ts` | 时长 / 体积 / 相对时间格式化、标题清洗、检索词生成 | VinylBox |
| `concurrency.ts` | 并发池 `TaskQueue`、去抖、节流 | VinylBox |
| `text-rules.ts` | 关键词规则匹配（自动打标 / 内容过滤 / 分类归一的共同内核） | VinylBox |
| `playback.ts` | 倍速档位、断点续播边界、睡眠定时 | EchoPod |
| `collections.ts` | 通用分组、文本归一化、关键词打分 | EchoPod |

本项目自身也已改为复用这些模块：原先散在 `lyrics.ts` 的解析实现、`downloader.ts` 的进度解析、
`utils/format.ts` 的格式化、`tagger.ts` 的匹配内核都已删除，改为引用 portable 层。
因此两边是同一份实现，修一处两边受益。

**同步方式**：任一项目新增模块后，把 `src/shared/portable/*.ts` 复制到另一侧同名目录即可。

## 技术栈

Electron 33 + React 18 + TypeScript + Vite（electron-vite），无 UI 框架依赖，样式为手写 CSS。

本地音频通过自定义 `media://` 协议供给渲染进程，支持 Range 请求以便拖动进度。

## 已知限制

- 需遵守 YouTube 服务条款，请仅下载你有权保存的内容
- 首次初始化组件需要能访问 PyPI（默认清华镜像，失败会回退官方源）
- 音频默认以 M4A 原始音轨缓存；MP3 需要转码，速度取决于 ffmpeg
